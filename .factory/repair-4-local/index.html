How it works

Review each step before it runs.

Use the same sequence for the bundled sample and your own reviewed runbooks.

  1. 01

    Choose a reviewed folder

    Add an owned directory of YAML files. The app records its path and content digest on your device.

  2. 02

    Fill the required values

    Enter typed values for choices, integers, paths, booleans, and secrets before preparing the run.

  3. 03

    Confirm the complete process

    Read the program, arguments, environment, working folder, and rollback note. Then type the runbook name to run it.

A legible local format

Keep maintenance steps in plain YAML.

Each runbook names a fixed program, argument array, and optional environment. Read and review the source before adding its folder.

Browse working examples →
specimen / restart-worker.yamlv1
id: restart-worker
name: Restart worker
risk: medium
parameters:
  - name: service
    type: choice
    choices: [indexer, mailer]
steps:
  - program: systemctl
    args: [restart, "{{service}}"]
rollback: Start the previous unit.

Safety details

See the whole command before consent.

⌘

Fixed program

A runbook names the executable. A parameter cannot change which program starts.

✣

Changed folders stop loading

Editing a reviewed YAML file requires another review before the folder becomes available again.

◌

Secret values are masked

Secret parameters are hidden in the review and redacted before local history is written.

↶

Rollback note stays nearby

The author’s recovery note appears before a run and beside its saved result.
